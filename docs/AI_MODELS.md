# AI and Machine Learning Stack

> **Audience:** model trainers, engine implementers, anyone changing
> `models/` or the neural paths in `engine/`.

---

## 1. Principle

No monolithic model. A **stack of six small, independently trainable,
independently compressible models**, each with a deterministic twin and a
parity contract.

## 2. The stack

| Component | Job | Architecture | Target footprint |
|---|---|---|---|
| **Pivot translator** | Source → English pivot | Quantized encoder–decoder Transformer (MobileNMT-style) + LoRA adapters | ~13 MB base + ~1–5 MB per adapter |
| **NSM decomposer** | Pivot text → NSM explication | Fine-tuned 1B–8B LLM, distilled to a 100–300M student | 100 MB–2 GB (tiered) |
| **NSM realizer** | NSM → Oarumi surface | Rule-based transducer primary; small seq2seq fallback | <10 MB |
| **Emotional TTS** | Oarumi text → expressive speech | Compact LM + neural codec (NeuTTS-2E / ParaStyleTTS style) | ~125M params, quantized |
| **Sign producer** | HamNoSys → SiGML → 3D animation | Graph diffusion model + procedural Animgen fallback | 50–200 MB |
| **ASR front-end** | Speech → text | Whisper tiny/base quantized via ggml | 32–190 MB |

## 3. Tiering

- **Tier A (rule-based)** — deterministic, microseconds, default for simple input.
- **Tier B (distilled student)** — 100–300M, INT8, ~100–300 ms on phone CPU.
- **Tier C (full teacher)** — 1B–8B, 4-bit, 1–5 s on phone, faster on desktop.

Tier B is the default neural path. Tier C is invoked only when Tier B fails
validation or the user requests maximum accuracy. Tier A is the fallback.

## 4. Training

### 4.1 Data sources

| Model | Training data |
|---|---|
| Pivot translator | Public parallel corpora for high-resource languages; **synthetic parallel data generated by the NSM pipeline** for low-resource languages |
| NSM decomposer | Curated human-verified explications, expanded by the Tier C teacher and filtered by the symbolic validator |
| TTS | Recorded or synthesized Oarumi speech with emotion labels; click-masked training; hummed-contour annotations |
| Sign producer | HamNoSys-annotated corpora + procedurally generated SiGML rendered to skeleton motion |
| ASR | Whisper base fine-tuned on Oarumi phonology (clicks, hums) |

### 4.2 Recipes

- Pivot translator: three-stage — base training → LoRA per language →
  INT8 quantization-aware training.
- NSM decomposer: fine-tune Tier C, then distill to Tier B with the
  symbolic validator in the loop.
- TTS: fine-tune with a dedicated **click token set** and **click-masked
  loss** so clicks are generated as distinct events rather than dropped.
- Sign: diffusion training on skeleton sequences; procedural Animgen as the
  always-available baseline.

### 4.3 Evaluation

- Pivot: BLEU/COMET on held-out; memory and latency budgets on target hardware.
- NSM: exact-prime coverage, cross-translatability (back-translation),
  human adequacy.
- TTS: MOS, click accuracy, hum-contour accuracy.
- Sign: visual realism rating, semantic correctness.
- ASR: WER on Oarumi audio test set.

## 5. Compression pipeline

Applied to every neural component:

1. Train or fine-tune at full precision.
2. Distill where latency matters.
3. Structured pruning (attention heads, FFN channels) with importance criteria.
4. Mixed-precision quantization: INT8 most weights, INT4 largest layers,
   with quantization-aware training.
5. Export: **TFLite** (Android), **ONNX Runtime** (Python), **ggml/GGUF**
   (CPU-first paths).

## 6. Manifests and integrity

Every model is described by a manifest in `models/manifests/`:

```json
{
  "name": "nsm-decomposer-tier-b",
  "version": "0.3.1",
  "artifacts": [
    {"path": "nsm-b-int8.tflite", "sha256": "...", "size": 12345678}
  ],
  "parity_suite": "tests/parity/test_nsm_decompose.py",
  "trained_on": "YYYY-MM-DD",
  "signature": "..."
}
```

- The app verifies SHA-256 before loading.
- Manifests are signed; the public key is pinned in
  `models/manifests/TRUSTED_KEYS`.
- Publishing a manifest is a high-risk change (AGENT.md § 4).

## 7. Offline and failover interaction

- All models are on-device after bootstrap (`docs/OFFLINE.md`).
- Every model sits behind the symbolic shield (`docs/RELIABILITY.md`).
- A model with no passing parity suite cannot be promoted to active.
